# Hosting a demo on Render

`render.yaml` describes a demo: one free web service that runs the API and serves the web app, and one free PostgreSQL database. It deploys the `main` branch, so every merged pull request is deployed.

This is for showing the system, not for running the shops. On the free plan the service sleeps when idle and takes about a minute to wake, and the free database expires roughly 30 days after it is created. Confirm the current limits on Render's pricing page.

## Steps

1. Sign in to Render and connect the GitHub account that owns this repository.
2. Choose **New**, then **Blueprint**, and pick this repository. Render reads `render.yaml`.
3. When asked, enter `SEED_ADMIN_USERNAME`, `SEED_ADMIN_NAME` and `SEED_ADMIN_PASSWORD` (at least 10 characters). They are stored by Render, never in the repository.
4. Apply. The first deploy builds the app, applies the migrations, creates the two divisions and the administrator, and starts.
5. Open the service's URL and sign in. The administrator has to choose a new password at first sign-in. Then, as CEO, they set up two-step sign-in: have a phone with an authenticator app (Google Authenticator, Microsoft Authenticator or similar) ready, scan the QR code, and keep the eight recovery codes somewhere safe. The same applies to every Finance and CEO account. `TOTP_ENCRYPTION_KEY` is generated by Render; do not change it afterwards.

## If the administrator's password is lost

On Render, open the web service's **Environment**, set `SEED_ADMIN_PASSWORD` to a new password (at least 10 characters) and add `SEED_ADMIN_RESET` = `true`, then **Save, rebuild, and deploy**. When the deploy is live, sign in as the administrator with that password and choose a new one. Then delete `SEED_ADMIN_RESET`, so later restarts leave the account alone. The reset unlocks the account, signs it out everywhere and is recorded in the audit log.

## Serving the web app from Vercel (optional)

`vercel.json` lets Vercel serve the web app while the API and database stay on Render. Vercel forwards every `/api` request to `https://onestop-demo.onrender.com`, so the browser only ever talks to the Vercel address: sign-in cookies and the cross-site request checks work unchanged.

1. In Vercel, choose **Add New → Project**, import this repository, and keep the root folder. `vercel.json` sets the install and build commands and the output folder.
2. Deploy, and note the address Vercel gives, e.g. `https://onestop-gam.vercel.app`.
3. On Render, add an environment variable `WEB_ORIGIN` to the web service with both addresses, comma-separated: `https://onestop-demo.onrender.com,https://onestop-gam.vercel.app`. Save; Render restarts the service.

Notes:
- The Render service still sleeps on the free plan. The first request after a quiet spell can take about a minute, and Vercel may give up waiting before Render wakes. Open the Render address a few minutes before a demo to wake it.
- Sign-in attempts through Vercel all arrive at Render from Vercel's servers, so the sign-in rate limit (30 attempts per 15 minutes) is shared by everyone using the Vercel address. Account locking after 5 wrong passwords is per account and unaffected.
- If the Render service is renamed, update the address in `vercel.json`.

## Loading the opening stock

The stock files are not in the repository. From a computer that has them in `data/opening-stock/`, point the import at the hosted database for one command, using the **External Database URL** from the database's page on Render:

```
# PowerShell
$env:DATABASE_URL = "<External Database URL>"; npm run import:opening-stock; Remove-Item Env:DATABASE_URL
```

The import refuses to run twice for a division that already has products.

## Moving from demo to real use

- Put the service and the database on paid plans, so the app stays awake and the database is kept and backed up.
- Schedule `tools/backup.sh` (see [BACKUP.md](BACKUP.md)) or turn on the host's own backups, and keep a copy elsewhere.
- Start from an empty database and import the real opening stock, rather than carrying demo sales and placeholder prices across.
- Make the repository private if business data or deployment details will ever be committed.
